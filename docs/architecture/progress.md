# Progress, bookmarks, history, stats

Saving and syncing listening progress, bookmarks, history and the statistics page.

Detail moved out of `CLAUDE.md` (review R8); keep it current when this area changes.

- Progress: `PlaybackProgressSaver` saves locally every 10 s while playing; `ProgressSyncer` sends the position through the ABS playback session every ~10 s and, when that fails, writes one coalesced row per book into `pending_progress` (Room v4); `PendingProgressFlusher` delivers the queue (on start, when the network returns, with backoff) and drops a queued row when the server holds something newer; a live sync the server took also deletes the older queued position of that book (never a queued mark), so it cannot be replayed over newer listening. The pure decisions (newest wins, timing, backoff, merge) are in `domain/playback/ProgressSync.kt`. Audiobookshelf progress is merged into local progress during the library sync; for both ABS and Plex the server progress is consulted by `PlaybackStarter` when a book opens (Plex is read only then, and when the queue flushes)
- Mark as finished starts the book over (owner's rule): `progressAfterMark` (`domain/playback/MarkFinished.kt`) writes finished AND position 0 (not finished stays 0, not finished); every copy of a merged entry is marked the same way. When the book or another copy of its entry is loaded in the player, `BookRepositoryImpl` calls its injected `rewindLoaded` (wired in `di/CommonModules.kt` to `PlaybackController.pause()` then `seekTo(0)` on the main thread, only if that book is still loaded) after the local marks and before any server call. The player's place from before that rewind can still reach `savePlaybackProgress` once (pause and seek are asynchronous): a save of the pinned finished book within `MARK_REWIND_GRACE_MS` (5 s) of the mark and more than `MARK_REWIND_SEEN_MS` (2 s) from the start is stored at 0 (`isSaveBeforeRewind`); the first other save ends that. The server's answer cannot bring the old place back: `progressAfterServerAnswer` keeps the mark's 0 when both are finished, `mergeServerProgress` leaves a finished local row alone when the server row is finished too (library sync, flusher, any later read), and `coalescePending` keeps a queued finished mark's place under a later ordinary position (the old place queued offline, or listening again). Servers: Audiobookshelf un-finishes a finished item whenever its time moves away from the end (its `applyProgressUpdate`), so a finished-at-0 push is two PATCHes (`absProgressPatches`, `domain/playback/AbsProgressPatches.kt`): not finished at 0 (moves the time to 0), then finished with no `currentTime` (the time does not change, the flag holds); a finished place past the start (heard to the end) and every ordinary place are one atomic PATCH as before; only an explicit not finished past the start is two (see below). The loaded book's live reports are silenced in the repository before the rewind and before any server call (`silenced`, rule `reportAfterMark`): `syncPlayback` holds back the old place (within the grace, paused or a tick read before the pause) and the pause at the start; the first report that is listening again (playing, or past the start after the grace) is sent and ends the silence, so time heard again reaches the server (where Audiobookshelf may then genuinely un-finish the book); a save no longer kept as finished or a not finished mark ends it too. The session close is not held back (at 0 by then). A failed rewind logs one `ProblemLog` line (book id and error type only). Plex scrobbles every track and Jellyfin sends MarkPlayed (both ignore the place). Host-tested only Playing a finished book again ends the finished state (owner's rule): the first listening again (a live report sent by `reportAfterMark`, or a pinned save past the start, `pinnedSave` = LISTENING_AGAIN: the old place within the grace is still the mark's 0, a save at the start keeps the mark) drops the pin of the book and of its other copies, so the row is saved not finished at the real place and the other copies are mirrored again. The rewind is tried twice; when both fail (`rewindFailed`, the player may still stand at the old place) nothing past the start ends the mark and no report goes out for `MARK_REWIND_FAILED_LIMIT_MS` (30 s, `rewindStillFailed`) or until a save at the start shows the player there; after that, listening there is listening. Only real listening counts: a save within 2 s of the start (Play then Pause) keeps a finished book finished (`staysFinishedAtStart`) and tells no server: no live report and no session close is sent below 2 s for a finished book (`silentAtStart`). Whenever the player's save turns a finished row into one that is not finished past the start (`playedAgain`: after Mark as finished, after Play again, after hearing it to the end, or a finished row from the server), a "not finished at the place heard" row (`markedFinished = false`) is queued in `pending_progress` in the same transaction as the local write (a cancelled saver cannot lose it; the saver never waits for a server) and the flusher is kicked. A queued not finished follows newer-server-wins like any row (a newer finish from another device stays, and a user's Mark as not finished queued offline works as before), with two exceptions in `flushDecision`: a Plex book's finished server row never drops it (an album stays all scrobbled while its live timelines move its time on), and a server row at 0 that is not finished never drops a queued not finished past the start (the first half of an Audiobookshelf pair whose place is still due); and `coalescePending` lets a newer place at the end replace a queued not finished (the book was heard to the end since). Delivery: Audiobookshelf gets two PATCHes for an explicit not finished past the start (`pushProgress(setNotFinished = true)`, from `markedFinished = false`; `absProgressPatches`: not finished without a time, which resets a finished item to 0 and would drop a time sent with it, then the place), so it keeps the place heard; Plex unscrobbles from that track on (`plexProgressPlan`; live timelines alone never un-finish an album whose tracks are all scrobbled); Jellyfin writes `Played = false` (its live progress writes carry it too) and clears its session pin. The other copies' servers follow through `ProgressMirrorPusher`.
- Bookmarks and History: `bookmarks` (Room v5; state SYNCED / PENDING_CREATE / PENDING_RENAME / PENDING_DELETE, identity = book + whole second) merge with the server's `GET /api/me` bookmarks through `mergeBookmarks` (`domain/playback/Bookmarks.kt`); `BookmarkSyncer` (`data/bookmarks`) pulls then pushes at start, when the network returns, after library syncs and a few seconds after a local change. `HistoryRecorder` records the position left on a big jump (`domain/playback/History.kt`, local only, last 10 per book). Player bottom row: Speed, Sleep timer, Bookmarks, History
- Stats: `ListeningRecorder` (`data/stats`, app-scoped, started by the application) watches `PlaybackController.state` and logs listening per local day and book into `listening_log` (Room v11; wall and book seconds, server, source). Time counts only while sound plays: no seeks, no buffering, no gaps over 5 s. The log is written every ~30 s and on pause or stop; after a failed write it waits 5 s, doubling to 5 min. `ListeningStatsImporter` (bound as `ListeningImport`) imports Audiobookshelf's `GET /api/me/listening-stats` once per server into `imported_listening_days` / `imported_listening_items`; `listening_imports` records which servers were imported. Each item row stores `loggedAtImport`, the app's logged total for that book at the import. A failed first import retries after 30 s, doubling to 30 min, and at once when the server row changes or the network returns. It is never tried while offline or while the server needs a sign-in. The stats page's Refresh imports again. ABS `days` keys are server-zone dates, read as phone-zone days. Rules: a day counts the larger of the log and the summed imported history; the source split adds the history beyond the log as ABS, so it sums to the total. All-time top lists add each book's server total minus `loggedAtImport` on top of the log, so they grow with new listening without a Refresh. Days are epoch days in an injected `DayZone` (`SystemDayZone` on Android; no java.time in commonMain). The pure rules (periods, day totals, streaks, top lists, series finished / to finish, heat grid, texts) are in `domain/stats` with host tests. `ui/stats` holds `StatsScreen`, `StatsViewModel` (route `stats`, from the Library top bar and Settings; a minute ticker follows midnight) and `HeatColors.kt`, where `HeatColorsTest` checks the level contrast in both themes. Host-tested only

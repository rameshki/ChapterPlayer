# Playback, player UI, Up next, offline playback

The Media3 service, the player screen, Up next, and how a book plays from the server or from the phone.

Detail moved out of `CLAUDE.md` (review R8); keep it current when this area changes.

- Playback: one Media3 `MediaLibraryService` (`PlaybackService`, in `shared/androidMain/.../data/playback`) hosts one ExoPlayer; the UI talks to it through `PlaybackController` (`AndroidPlaybackController` wraps a `MediaController`). Audiobookshelf is asked for a playback session (`POST /api/items/{id}/play`); a book with several audio files plays as ONE timeline (one media item per file; `domain/playback` maps book position to file and offset). Audio is fetched with the bearer token added per request by `AuthorizingDataSourceFactory` (refreshed once on a 401). The pure rules (timeline, sleep timer, rewind on resume, skips, speeds) are in `domain/playback` with host tests; the service behaviour itself is checked on an emulator (`adb shell dumpsys media_session` shows state and position). Up next (branch `stage-4/up-next`, host-tested only): an ordered queue kept on this phone in `up_next` (Room v15: bookId, position, addedAt; auto-migration; `UpNextRepository` / `RoomUpNextRepository` in `data/upnext`, every change one read-modify-write under a lock through `edit`). Pure rules in `domain/playback/UpNext.kt`: a row stands for its whole merged entry (`resolveUpNext` finds it through any copy's id; a second row of one entry and a gone book are stale and dropped when the queue advances), `editUpNext` (Play next = front, moving a queued book there; Add = end, a queued book keeps its place; never the book in the player), `moveInUpNext`, `removeFromUpNext`, `planUpNext` (first entry with a copy that can play; the copy by `resumeCopy`, downloaded first, else played last, among `upNextCanPlay` copies: downloaded, or online without "Downloaded only" on a server that answers; entries that cannot play are skipped and stay queued) and `endedWhilePlaying` (advance only when `PlaybackState.ended` follows a state of the same book with playWhenReady, no error, at most 5 s of book times the speed before the end, so a skip onto the end does not count, and no sleep timer due within 3 s of the end); `carriedSleepTimer` / `sleepLeftAtEnd` carry an "After" timer's time left to the next book (`SleepTimer.After.durationMs`). `PlaybackState.ended` comes from `Player.STATE_ENDED` on Android and `AudioEngine.ended` on iOS. `UpNextAdvancer` (`data/playback`, commonMain, app-scoped, started by the Application and iOS `initKoin`, runs on the main dispatcher) starts the pick through `PlaybackStarter` ("Downloaded only" respected), removes the entry once started, keeps it and posts the reason on a failure (no retry until another end), and takes any book that starts playing from anywhere (app, car, widget) off the queue; it cancels itself when another book loads or the ended book is played again, re-checks the player right before the start, and runs inside `BackgroundWork` (iOS `UiKitBackgroundWork`, bound in `iosUpNextModule`); its notes (skips, failures) go through `UpNextNotices`, shown as a snackbar by `AppNavigation` over any screen. UI: "Play next" / "Add to Up next" ("Remove from Up next" when queued) in `BookActionsSheet` and on Book details (`BookDetailsViewModel.onUpNextClicked`, results through `message` on the page too); the player's bottom row has Up next (`UpNextSheet`, `UpNextViewModel`: move up / down, remove, Clear all); Home's Up next shelf after the Resume card (never filtered); the car's "Up next" folder (`CarData.upNext`, node `upnext`, only while non-empty)
- Player UI: `ui/player` holds the full player (`PlayerScreen`, speed/sleep/chapter sheets), the mini player (above the tab bar, hidden on the player and Settings routes) and `PlayerViewModel`, all reading `PlaybackController.state`. `PlaybackStarter` (`data/playback`) is the one way to start a book (Home, details); `PlaybackProgressSaver` saves progress app-wide. Pure display rules live in `domain/playback/NowPlaying.kt`, `domain/browse/ResumeCard.kt` and `ContinueSeries.kt`. The notification opens the player through the `open_player` intent extra. The player's top-right More options (three dots) menu is `PlayerMenuButton` with its own `PlayerMenuViewModel` (menu state and actions; results show as a snackbar): Book details, More by <author> (only when the author has other books), Open series (only with a series), the download item (Download / Pause / Resume / Try again / Remove download with a confirmation; of the loaded copy, Plex too), Mark as finished / not finished (Audiobookshelf and Plex; for Plex it scrobbles / unscrobbles every track) and Settings. `BookRepository.markFinished` changes the local progress first (rules in `domain/playback/MarkFinished.kt`), then PATCHes `/api/me/progress/{id}` and adopts the server's answer (an un-finished book is reset to 0 by the server); when the server cannot be reached the mark waits in `pending_progress` (Room v8, column `markedFinished`) and the flusher delivers it. `PlaybackProgressSaver` saves through `savePlaybackProgress`, which reads and writes under the same lock as `markFinished` and keeps a finished mark the user made while that book is loaded (re-derived on every save, never latched; a finished row merged from the server does not count)
- Offline playback: `PlaybackStarter` asks `choosePlaybackSource` (`domain/playback/PlaybackSource.kt`) whether a book streams, plays from the phone (any complete download, ABS or Plex) or cannot play (offline and not downloaded: "Needs a connection to play"; "Downloaded only" blocks streaming except from the car). `LocalBookFiles` (`RoomLocalBookFiles`) hands out a DONE download's files only when each is on disk at its full size (disk checks on the I/O dispatcher). A book folder that cannot be seen (an unmounted SD card) only means "not playable now"; a folder that is there with a file gone or of the wrong size marks the download FAILED and resets the missing files so Try again fetches them. Removing a download first tells the player (`DownloadRemovalListener` → `PlaybackController.releaseLocalFiles`), which stops a book playing from those files. The controller gets `AudioOrigin.Phone`: online it still opens an ABS session (live sync; if that fails the book plays without one), offline it plays with no session and `ProgressSyncer` queues the position. `playableFromPhone` (`data/playback/PlayableBook.kt`) matches session tracks to files by the ino in their `/file/{ino}` address: the session's timeline when it lists exactly these files in this order, else per-file lengths (the session's for that file, else `download_files.durationMs`, Room v7; a single file uses the book's length). Lengths learnt from a session are saved, and `DownloadLengthFiller` fills missing ones from `GET /api/items/{id}` each time the phone comes online, so downloads made before v7 play offline too. A Plex download plays the same way: online the app's own Plex session is opened (its tracks are part paths; `PlaybackTrack.fileId` carries each track's rating key, so the session is matched to the files like an ABS one) and keeps sending timelines and scrobbles; when the session's tracks are not exactly the downloaded files in order (the album changed) the book streams with that session instead, so no position is reported onto the wrong track; offline there is none and the position is queued; a Plex download with no stored chapters gets one chapter per file ("Part 1", ...). The player reads `file://` items through `DefaultDataSource` and HTTP through `AuthorizingDataSourceFactory`. The car's Downloaded tab lists the downloaded books
- Android 15 audio focus (R5, targetSdk 36): focus is granted only to the top app or an app with a foreground service. A Play from outside the app (headless widget Play, the car, a media button) can reach ExoPlayer before Media3 has started the service in the foreground; the refused request turns playWhenReady off with `PLAY_WHEN_READY_CHANGE_REASON_AUDIO_FOCUS_LOSS` before any sound, and Media3's `onForegroundServiceStartNotAllowedException` never fires (Media3 1.11 starts the service early only on API 31 to 32). `AudioFocusStartWatch` (`domain/playback/AudioFocusStart.kt`) tells that apart from a real loss (sound already played, a pause by the person, the app in front, `isAppInFront`) and `PlaybackService.onPlaybackRefused` reacts as for a refused foreground start (`foregroundRefusalAction`: pause and "Tap to keep listening"). Host-tested only; whether Android refuses focus at a widget start at all is a device check

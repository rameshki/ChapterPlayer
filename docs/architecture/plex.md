# Plex

Plex connection choice, sync status, library, playback and progress.

Detail moved out of `CLAUDE.md` (review R8); keep it current when this area changes.

- Plex connection choice (Stage 4 step 3): pure rules in `domain/plex/PlexConnections.kt` rank plex.tv's connections (local, the raw local `http://<address>:<port>` for a `*.plex.direct` local name, remote, relay; IPv6 only when nothing else), probe them (`pickConnection`: two at a time, a lower-ranked answer waits a 1.5 s grace window for better-ranked ones, a timeout is tried once more, and a local plex.direct name that is not found moves the raw local address ahead of remote; `probeAll` for Test connection), classify errors by type name (`classifyConnectionError`, no JVM types in common code) and word the result (`connectionNote`). `PlexConnectionManager` (`data/sync`) writes the winner into the server row's `baseUrl` (so every caller uses it) and keeps the ranked list, the last probe and its note in `ServerStatusStore` (a Preferences DataStore `server_status`, one JSON record per server; no Room change). It re-probes after a connection failure (sync: retry once on the new address; playback start: `BookRepositoryImpl.onConnectionFailure`), when `ConnectivityMonitor.currentNetwork` changes (started by the Application) and before the first sync of a server with no choice yet; at most once per 30 s unless forced (Sync now, Test connection). A server saved before this asks plex.tv for its list (`PlexTvCandidateLookup`, matched by address). The probe (`GET /identity`, client `createProbeHttpClient`: 5 s timeouts, no redirects) sends NO token, and only an answer naming the server's `machineIdentifier` (plex.tv's `clientIdentifier`, kept as `machineId`) counts; a bare 2xx (captive portal, another Plex server) loses. Besides the address in use, the token goes only to `verifiedUris` (`ServerConfig.alternateBaseUrls`, filled by `ServerRepositoryImpl`; `plexAddressesOf`): https connections that answered as the server, and a plain http (raw LAN) one only while verified on the current network. On a network change plain http verifications are dropped and a server on a raw LAN address is moved back to its first https connection before it is probed again; a sync of an unverified plain address probes first. After a remote or relay pick the local connections are tried again 60 s later. A switch the caller did not ask for (`onSwitched`) syncs that server again (`requestSync`), so stored cover addresses follow the address in use. A Plex edit that changes the address or token by hand forgets the connections (`forget`). Probes and plex.tv reads run on the injected IO dispatcher. Built against fixtures and fakes; NOT tried on a real Plex server
- Sync status: `LibrarySyncCoordinator.serverStatus` gives each server's phase (`Idle` with last success and cached book count, `Syncing`, `Failed` with a short reason from `syncFailureReason`), the connection in use and the last Plex probe; the last success and error persist in `ServerStatusStore`. `syncNow(serverId)` and `syncNowAll()` (the Library refresh button and pull to refresh) force a sync, still one per server at a time. Settings, Servers (`ServersViewModel`, wording in `domain/settings/ServerStatusText.kt`) shows each row with Sync now and, for Plex, Test connection (a dialog of every connection with OK or the reason; never a token)
- Plex (Stage 4): in a Plex music section each audiobook is an ALBUM (the top level lists artists). `PlexLibrarySource` (`data/source`) lists `/library/sections/{key}/all?type=9` in pages of 200 (`fetchAllPlexItems`, `data/remote/plex/PlexPaging.kt`; follows `totalSize` even when a server sends smaller pages); a server that answers with artists has each artist opened for its albums. Book id `plex_<album ratingKey>`, author = album `parentTitle`, no narrator. A sync reads the section list once; a section that fails keeps its cached books (`SourceSnapshot.failedLibraries`) and is reported, only all sections failing fails the sync. Opening a book (`fetchBookDetails`) reads the album, its tracks (`/children`) and the first track with `includeChapters=1` (every track, 4 at a time, when that one has chapters or failed; a track whose detail fails is one chapter); `plexBookContent` (`domain/plex/PlexBookContent.kt`) builds the chapters across tracks and the ordered `PlexTrack`s (part key, length, container, size) that playback will use, and details store the book's length (a section listing has none). The details' description is the album's `summary`, else the first track's non-blank one (`PlexBookContent.summary`, a track detail's before the track list's), else none; a book several servers have shows an Audiobookshelf copy's description when one has it (`mergedDescription`, `domain/browse/DetailsLogic.kt`; a Plex page asks the ABS copies' details after its own, outside the load job, three at once at most, kept for the app session in `CopyDescriptions` (Koin single; failures are asked again)). The token is never in a stored address: API calls send `X-Plex-Token`, and covers get it from `PlexCoverInterceptor` (`data/images`, installed as Coil's image loader by the Application, whose Ktor client follows redirects itself and drops `Authorization` and `X-Plex-Token` when one leaves the origin: `data/remote/OriginSafeRedirects.kt`) only for addresses under a signed-in Plex server (`plexTokenFor`, `domain/plex/PlexImageAuth.kt`). Room v9 changes no table: its migration (`Migration8To9`) dropped the Plex rows stored as artists with the token in their addresses, plus progress, queued progress, history and bookmarks for `plex_` ids. Playback (step 2): Plex books stream like Audiobookshelf books that are not downloaded, and download like them (see Downloads; a finished Plex download plays from the phone, offline too). `PlexLibrarySource.startPlayback` reads the tracks and chapters fresh (`fetchContent`) and builds the app's own session (Plex has none): one media item per track on the one timeline, each address the part path under the server address with no token (`plexPlaybackTracks`, `domain/plex/PlexPlayback.kt`). `AuthorizingDataSourceFactory` adds `X-Plex-Token` per request only for addresses under a Plex server (`openAuthorized`), and a 401 is `SignInRequiredException` ("Sign in again", no refresh: Plex tokens are long lived). Audio is fetched through `OkHttpDataSource` with redirects off; `openStream` follows them by hand (`redirectTarget`: at most 5, never https to http, and a request carrying a token, ABS bearer or Plex header, only to the same scheme, host and port, else `UnsafeRedirectException`). A track without a file or without a known length fails the start with a safe message. A 401 on a Plex playback or progress call (start, timeline, scrobble, track list) blanks the server token (`markSignedOut`, wired in Koin) and is `SignInRequiredException`, so the flusher stops and Settings shows "Sign in again". Cover art (notification, lock screen, Bluetooth, the car's Now Playing): each track item's `artworkUri` is the app's cover address (`bookArtworkUri`, no token), and the session's `BitmapLoader` (`CoverArtworkBitmapLoader`; its `LastLoadCache` reuses only a running or successful load, never a failed one, unlike Media3's `CacheBitmapLoader`) resolves it in the service through `CoverBytesLoader` (commonMain `data/images`; Android `AndroidCoverSources`): a downloaded book's `cover.jpg` first (offline), else the book's own server only (`coverRequestAuth`: ABS bearer / Plex `X-Plex-Token` in a header, the origin-safe image client; Plex only after `PlexConnectionManager.forCoverRequest`, which refuses a plain http address not verified on this network like `forTokenRequest` but never probes), scaled to 512 px JPEG 85 with sampled decoding (`AndroidCoverScaler`, rules in `domain/covers/CoverRules.kt`), 8 covers in memory; the book and server are read before the cache, so a removed server's books have none at once and a signed-out server's book only its downloaded cover; any failure is no cover (a 401 is not refreshed, a failed book is not asked again for 60 s). Bytes are not embedded in the metadata (one item per file would multiply them across the controller binder); other addresses are refused by the loader. Known limit: artwork embedded in the audio file (ID3 / MP4 `covr`, which Media3 prefers over the address) is decoded at full size by `decodeBitmap` (as Media3's default loader did; an out-of-memory is caught as no cover). Host-tested; not yet seen on a phone. Resume: `fetchProgress` reads the track list (`viewOffset`, `viewCount`, `lastViewedAt` per track) and `plexServerProgress` gives the finished tracks plus the offset in the track in progress, finished when every track was played, updated at the newest `lastViewedAt`; the starter weighs it against local progress (newest wins). Progress push: `ProgressSyncer` reports Plex books too; `syncPlayback` sends `GET /:/timeline` (ratingKey, key, state `playing`, `paused` for the report on pause, `stopped` only from `closePlayback`, time and duration in the track, `identifier=com.plexapp.plugins.library`, client headers from `PlexApiService`, whose client identifier is required) for the track that holds the position, and `GET /:/scrobble` once per session for a track that playing went through (its end lies between two reports no further apart than the time listened at 3x plus 5 s; a seek over tracks scrobbles nothing) or whose last 5 s are reached (`plexCompletedTracks`). A session that never reported (a rolled-back start) closes silently. Once the book is set finished (`pushProgress` with finished, e.g. Mark as finished while it plays) its live session sends nothing more, so a later timeline cannot undo the mark; set not finished, it reports again. `plexServerProgress` counts every track played with at most one offset left as finished. An unknown session (after a restart) fails, so the position is queued in `pending_progress` as for ABS; `pushProgress` (queue, Mark as finished / not finished) follows `plexProgressPlan`: unscrobble the played tracks from the position's track on, a stopped timeline for the offset, scrobble the unheard tracks before it (finished = scrobble every track). The library sync merges no Plex progress (that would need one call per book). Built against recorded-shape fixtures in `fixtures/plex` and mock servers; tried on a real server and phone since: PMS keeps NO `viewOffset` for audio tracks of this library type (neither `/:/timeline` nor `/:/progress` stores it; Plex Web offers no resume), so Plex never holds the position of these books (the Audiobookshelf copy does, and the Plex copy follows it)

## Goal
Play ABS and Plex books on the iPhone through the shared `PlaybackController` contract: load a book (one timeline from several files/tracks, as on Android), play/pause/seek/skip 15 and 30/speed/chapters/sleep timer, background audio, lock screen and Control Center controls with title/author/chapter/progress, headphone and Bluetooth buttons, interruptions (calls, Siri, other audio) and route changes, progress save/sync/Plex reporting through the existing shared code (`PlaybackProgressSaver`, `ProgressSyncer`, `PlaybackStarter`). Downloads/offline files on iOS are step 5, but the controller must already accept `AudioOrigin.Phone` file URLs.

## Design (decided)
- `IosPlaybackController : PlaybackController` in `iosMain`, Kotlin/Native over `platform.AVFoundation` (AVPlayer/AVQueuePlayer or one `AVPlayer` with `AVPlayerItem`s built per file/track; use the shared timeline mapping in `domain/playback` for book position <-> file+offset, durations from the session/tracks/book as on Android `playableFromPhone`/`PlaybackMapping`), `MediaPlayer` (`MPNowPlayingInfoCenter`, `MPRemoteCommandCenter`: play, pause, toggle, skip forward 30 / back 15 (preferredIntervals), change playback position, next/previous chapter), `AVAudioSession` category `.playback` (spoken audio mode `AVAudioSessionModeSpokenAudio`), activation on play, interruption + route-change notifications (pause on headphones unplugged; resume after an interruption only if it says shouldResume), `UIBackgroundModes: audio` in `iosApp/project.yml` Info.plist.
- **Auth for streaming:** ABS audio needs the bearer token per request and refresh on 401; Plex needs `X-Plex-Token`. AVPlayer cannot take per-request async auth, so use `AVURLAsset(url, options: {AVURLAssetHTTPHeaderFieldsKey: headers})` with a token resolved at load time (and refreshed by recreating the item at the current position on a 401/failed item). Never put the token in the URL. Respect the shared origin-safe rules (the item URLs come from the session/track list for the server's own origin; no custom loader that follows redirects with the token to another host: AVFoundation follows redirects itself and DOES resend custom headers, so prefer an `AVAssetResourceLoaderDelegate` proxy ONLY if needed; first choice: if the server answers with a redirect to another host the item fails and the error is shown). Document the limitation if you keep the header approach.
- **State:** `PlaybackState` (position, duration, chapters, speed, playing/buffering/error, bookId) updated from `addPeriodicTimeObserver` (about 2 per second while playing, same cadence as Android's ticker) and KVO/notifications (item status, rate, `AVPlayerItemDidPlayToEndTime`, stalls); `activeSession` and `AudioOrigin` handling identical to Android; errors become `PlaybackStartException`/`state.error` with safe messages.
- **Sleep timer:** reuse the shared `SleepTimer` rules (time-based and end-of-chapter) driven by the controller's clock; fade is optional.
- **Threading:** AVFoundation objects live on the main queue; the controller exposes the shared StateFlows; all observer callbacks marshal to main; no `runBlocking`.
- **Wiring:** `iosPlatformModule` binds `IosPlaybackController` instead of the stand-in; `PlatformFeatures` on iOS turns playback ON (downloads and car stay off); the mini player/full player screens then work as on Android; `ListeningRecorder` and `ProgressMirrorPusher`/syncers start on iOS (extend `KoinIos` onStarted like the Android Application); the foreground-only sync rules stay.
- **Pure parts in common with tests (run on Kotlin/Native in CI):** anything computable without AVFoundation (item/segment planning, interruption/route decisions as pure functions `decideAfterInterruption`, remote-command mapping, now-playing info assembly as data classes) goes to `commonMain` with tests.

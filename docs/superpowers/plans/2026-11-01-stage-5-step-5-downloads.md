## Goal
Download ABS and Plex books on the iPhone (resumable, one request per file with Range, same rules as Android: Wi-Fi-only setting, storage limit, one book at a time, space check, pause/resume/cancel/remove, progress with speed/ETA), play them offline through the existing shared offline path (`choosePlaybackSource`, `playableFromPhone`, `AudioOrigin.Phone`), the Downloads tab and the Download controls on details/player menu. Downloaded files must live where iOS does not purge them and must NOT be backed up to iCloud.

## Design (decided)
- **Move the downloader core to commonMain on kotlinx-io** (`kotlinx.io.files.SystemFileSystem`, `Path`, `RawSink/Source`; kotlinx-io is already on the classpath via Ktor): `FileDownloader`, `BookDownloader`, `DownloadSource` + the ABS/Plex adapters, `DownloadLengthFiller`, `DefaultDownloadController`, `DownloadLocation` abstraction, `LocalBookFiles` real implementation. Replace `java.io.File/RandomAccessFile/FileOutputStream/nio Files` with a small `DownloadFiles` port (length, truncate/open append at offset, fsync, atomic rename, delete recursively, exists, free space, listing) with an Android implementation on java.io/nio (behaviour identical to today) and an iOS implementation on `NSFileManager`/`NSFileHandle` (append at offset, `synchronizeFile`, `moveItemAtPath` atomic rename, `NSURLResourceKey`/volume capacity for free space). Keep package names. The Android WorkManager scheduler stays Android; `DownloadScheduler` is the port.
- **iOS location:** `<Application Support>/downloads/<serverId>/<bookId>/` created with `NSURLIsExcludedFromBackupKey = true` on the `downloads` folder (set it right after creating, and again if the folder is recreated); no SD-card/volume choice on iOS (one volume), the "download location" settings row is hidden on iOS.
- **iOS scheduling (`IosDownloadScheduler`):** downloads run in the app process with the shared Ktor-based `FileDownloader` while the app is active; when the app goes to the background, extend with `UIApplication.beginBackgroundTask` (finish the current chunk, save offsets, pause cleanly on expiry; resume on foreground); additionally, on iOS 26+ request a `BGContinuedProcessingTask` (user-initiated, with progress reporting and a title) so a long download continues in the background with the system progress UI, guarded by availability checks and a clear fallback when the API is missing or refused; register the task identifier in Info.plist (`BGTaskSchedulerPermittedIdentifiers`) and `UIBackgroundModes` as needed (`processing`). Wi-Fi-only uses the shared `mayDownload(policy, onUnmetered, online)` with the `NWPathMonitor` flags (`isExpensive`/`isConstrained` = metered; add the metered flag to `ConnectivityMonitor` for iOS; Android already has it). On app start, re-enqueue unfinished downloads like Android's restore.
- **Darwin engine notes:** Darwin ignores `connectTimeoutMillis`; the stall watchdog is ours, keep it. No URL cache and no redirect-with-token (as step 1).
- **Notifications:** local notification permission through `UNUserNotificationCenter` (`IosNotificationPermission`); progress is shown in the app and by the BGContinuedProcessingTask UI; a local notification only on completion/failure while backgrounded.
- **Offline playback:** `file://` items already supported by the iOS player (`AudioOrigin.Phone`); verify the item builder uses file URLs without token headers and that a missing file reports the shared "Try again" path; `LocalBookFiles` real implementation for iOS (existence/length checks on the IO dispatcher).
- **Features:** `PlatformFeatures` on iOS turns downloads ON (car stays off); remove the stand-ins from the iOS graph (keep them for tests if useful); the Library "Downloaded" filter and the Download group in the Filter sheet come back on iOS; Settings > Downloads page works (Wi-Fi only, storage limit, used/free) without the location choice.

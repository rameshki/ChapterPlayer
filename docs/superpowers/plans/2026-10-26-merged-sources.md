# One entry for a book that several servers have (Phase 1)

Branch `stage-4/merged-sources`. Read `CLAUDE.md` (Browsing, Library views, Playback, Downloads, Car, Widgets, Settings hub) first. Robert approved this design (2026-10-26):

- A book present on more than one server (Audiobookshelf and Plex) is shown as ONE entry. A small mark ("2 sources" or the two source labels) shows it has several. Play and Download on the details page ask which source to use through a small sheet (per source: ABS/Plex label, server name, downloaded or not, reachable now or not; downloaded first), unless the default setting decides.
- Settings choice "When a book is on several servers": Always ask / Prefer Audiobookshelf / Prefer Plex / Prefer the downloaded copy. Default: prefer downloaded, otherwise Audiobookshelf, otherwise ask. (Settings hub: add it to the Downloads and offline page or a new Library page row; keep it small.)
- Matching is conservative: same normalised title (case, punctuation, diacritics folded with `domain/browse/AlphaKeys.kt`, leading "The/A/An" ignored, and "(Unabridged)"/"(Abridged)" style suffixes removed) AND same normalised first author AND lengths within 2% (or within 5 minutes; when either length is 0 do not merge). Never merge two books from the SAME server. A book can be in a group of at most one book per server.
- Mistakes are fixable: "Not the same book" (split) on the details page of a merged book, and "Merge with…" (pick from a search list of the other books) on any book; both persist across syncs and restarts.
- Phase 2 (NOT in this task): mirroring progress between sources. Do not build it; but keep the design ready (the group knows its members).

## Tasks (test-first, host tests; commonMain portable: no JVM-only calls such as putIfAbsent, computeIfAbsent, String.format, java.* since CI iOS compiles commonMain with Kotlin/Native and Windows cannot)
1. **Pure rules** `domain/browse/MergedSources.kt`: `mergeDuplicates(items: List<BrowseItem>, overrides: MergeOverrides, preference: SourcePreference, onlineServerIds: Set<String>): List<BrowseItem>` returning one entry per group with the chosen primary item (`BrowseItem` gains `otherSources: List<BrowseItem> = emptyList()`; or an equivalent) and ordered members; the primary is chosen by the preference rules (downloaded copy first, reachable server before unreachable, then the preference, then ABS). `MergeOverrides(splits: Set<Pair<bookId,bookId>>, merges: Set<Pair<bookId,bookId>>)`: a split forbids the automatic match for that pair, a manual merge forces it (even when titles differ). Deterministic and order independent. Tests: matching (case, punctuation, article, unabridged suffix, diacritics, length tolerance, zero length), same-server never merge, transitive groups, splits and manual merges, primary choice for every preference.
2. **Persistence:** `book_merges` overrides (Room table with auto-migration, or a DataStore if simpler; justify in the report) via a small repository; `AppSettings.sourcePreference` (+ Settings UI row with the four options).
3. **Where merging applies:** one place in the data flow that feeds Library (all views and groupings, counts, the A to Z scroller keys, server filter: a merged book matches the server filter if ANY member matches and then the primary shown should prefer a matching member), Home shelves/Resume card/Continue series, Search, Downloads tab (downloads are per member: show the downloaded member), car browse tree and voice search, widgets: they all use the merged list's primary. Progress shown on a merged tile = the member with the newest `lastPlayedAt` (the furthest/most recent; document the rule and test it).
4. **UI:** the tile/row mark (a small "2 sources" pill, bottom right where the source badge sits; it shows even with a single server type), details page of a merged book: a "Sources" section listing members with their labels; Play / Download / Resume use the source sheet (`ModalBottomSheet`) unless the preference decides; remembers nothing else. Split / Merge-with actions in the details overflow area (and the player ⋮ menu for the playing book: "Not the same book" only). Accessibility labels include "available from Audiobookshelf and Plex".
5. **Edge rules:** a merged book where one member is Plex and the other downloaded ABS offline -> primary is the downloaded ABS; Plex-only reachable -> Plex; the sheet greys unreachable sources with the reason. Deleting a server or a book disappearing from a source just shrinks/dissolves the group.
6. Docs: `CLAUDE.md` (Browsing line) and ROADMAP Stage 4 (unified library item, honest: host-tested only).

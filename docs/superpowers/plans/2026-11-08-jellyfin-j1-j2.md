# Jellyfin J1 and J2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Jellyfin as a third book source: J1 = sign in, browse, stream and read the resume position; J2 = send progress back (live session, queue, Mark as finished), and one entry with up to three copies (ABS, Plex, Jellyfin) with mirrored progress.

**Architecture:** A new `ServerSource.JELLYFIN` with its own small Ktor client (`JellyfinApiService`), a `JellyfinLibrarySource : LibrarySource` and a `JellyfinSignIn` port, all in `commonMain`, wired into the same Koin lists as the ABS and Plex sources, so the repository, sync, merging, player and queue work unchanged. Pure rules (header, ticks, version gate, mapping, progress bands and the call plan) live in `domain/jellyfin` with commonTest tests; HTTP parsers are tested against synthetic fixtures in `androidHostTest`. The token travels only in the `Authorization: MediaBrowser ...` header (never in a URL); covers are anonymous.

**Tech Stack:** Kotlin Multiplatform 2.4, Ktor (OkHttp / Darwin), kotlinx.serialization (`ApiJson`), Koin Classic DSL, Compose Multiplatform, Media3 (Android), AVPlayer via `StreamAuthorizer` (iOS), Room (unchanged).

**Spec:** `docs/superpowers/specs/2026-11-07-jellyfin-source-design.md` (APPROVED 2026-11-08 by Robert, with Quick Connect added to J3). Read it with this plan; section numbers below refer to it. The builder's calls in its section 12 are approved defaults.

## Global Constraints
- Minimum server **10.10.7** (setup refuses below **10.10** with "This Jellyfin version is too old (10.10 or newer is needed)"); chapters and narrators need **12.0** or newer (10.10/10.11: one chapter, author from `AlbumArtist`, no narrator).
- Book id **`jf_<Id>`** (the 32-hex item id exactly as the server sends it).
- Ticks: **10,000,000 per second** (1 tick = 100 ns; ms = ticks / 10,000).
- List call, fixed: `GET /Items?ParentId={view}&IncludeItemTypes=AudioBook&Recursive=true&Fields=People,Overview,Genres,DateCreated,ProviderIds&EnableUserData=true&EnableImageTypes=Primary&StartIndex={n}&Limit=200&EnableTotalRecordCount=true` (page size **200**, follow `TotalRecordCount`).
- Details and playback call, fixed: `GET /Items/{Id}?Fields=Chapters,People,Overview,Genres,Studios,MediaSources`.
- Header on every call: `Authorization: MediaBrowser Client="ChapterPlayer", Device="<Android|iPhone>", DeviceId="<id>", Version="<app version>", Token="<token>"` (no `Token` part before sign-in). Client fields carry only letters, digits, `-`, `.` and spaces; the token is URL-encoded. Never `X-Emby-*`, never `api_key` / `ApiKey` in a URL.
- DeviceId = **`"chapterplayer-" + <per-install id> + "-" + <server row id>`**, computed, never stored; the per-install id is `PlexClientIdentifier.value` behind a new `InstallId` interface (Plex's stored value does not change).
- Audiobook thresholds: defaults **5 min / 5 min** (`MinAudiobookResume` / `MaxAudiobookResume`, read from `GET /System/Configuration` once per successful sync, kept in memory per server; unreadable = 5 / 5).
- Merge rule unchanged: lengths within **2% of the longer or 5 min** (either is enough); same normalised title and first author; never two copies of one server.
- Ties by kind: **ABS > Jellyfin > Plex** (member order final tie-break and metadata order).
- Tokens, passwords and Quick Connect secrets are never logged, never in `toString`, exception messages, notifications, media metadata or Diagnostics output. 401 blanks the token and is `SignInRequiredException` ("Sign in again"); 403 is "The server does not let this account play this book".
- All Jellyfin code in `commonMain`; no JVM-only APIs (`String.format`, `java.*`, `System.currentTimeMillis`, `putIfAbsent`, `computeIfAbsent`, `sortedMapOf`); random ids from `kotlin.random.Random`, time from an injected `nowMs`.
- **Room unchanged** (no version bump, no migration): `JELLYFIN` is stored as the enum name in existing string columns.
- `./gradlew :shared:compileKotlinIosSimulatorArm64` must pass on Windows at the end of every task (with `:shared:testAndroidHostTest` and `:androidApp:assembleDebug`).
- Existing files are CRLF: edit them from Python with `encoding='utf-8'`, preserving `\r\n` (or the Edit tool, then grep for stray LF); new files may be LF.
- Fixtures in `shared/src/androidHostTest/resources/fixtures/jellyfin/`: real structure from the v12.4 DTOs, **synthetic** names, ids (fresh random 32-hex), paths and tokens only. The repo is public.
- Commits end with exactly:
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`
  `Claude-Session: https://claude.ai/code/session_01M55YRaxmRRG8NmDaVhSmey`
- Branches `stage-j/<name>` (one per stage is fine: `stage-j/j1`, `stage-j/j2`). Implementers never push and never dispatch subagents. One gradle command at a time, JDK 17.

## Review Focus
1. **A server address with a path or a trailing slash** (`https://example.test/jellyfin/`): every API call, the cover address and the stream address keep the path exactly once, and the token header is matched to the server by the same prefix rule as ABS. Pinned by `address with a path keeps it in every call` (Task 3) and `stream and cover addresses under a path prefix` (Task 7).
2. **An item missing optional fields** (no `RunTimeTicks`, no `MediaSources`, no `Chapters`, chapters unsorted or past the end, empty `People`, no `AlbumArtist`): it maps to a book that never crashes the list (duration 0, author "", one "Part 1" chapter), and playback fails with a safe message instead of an exception. Pinned by `item with missing fields maps safely` (Task 5) and `start without media source fails with a safe text` (Task 7).
3. **A reverse proxy or another app answering the address** (HTML 200, a JSON without `ProductName`, a redirect to a login page): setup says "This is not a Jellyfin server" and sends no password. Pinned by `html answer is not jellyfin` (Task 4).
4. **Two Jellyfin servers, or the same one added twice**: each row has its own DeviceId, so signing in on one never logs the other out; Sign in again on an address that now answers with another server `Id` is refused. Pinned by `two rows get two device ids` and `sign in again on another server id is refused` (Task 4).
5. **Odd characters in header values** (a token with `+`, `%` or `"`, an app version like `0.4.1-debug`): the header stays well-formed and the server would decode the same token. Pinned by `header escapes token and client fields` (Task 2).

## Goal
Everything that is only "Ktor + kotlinx.serialization + Room + DataStore + coroutines" lives in `commonMain`; the genuinely platform parts sit behind small interfaces with an `androidMain` and an `iosMain` implementation; the iOS app starts Koin and shows the REAL Settings -> Servers screens (add an ABS or Plex server, see its sync status) instead of the placeholder. No playback, downloads, sync glue or library screens on iOS yet (steps 2 to 5).

## Tasks (test-first where there is logic; Android host tests stay green throughout; commonMain must avoid JVM-only APIs: `putIfAbsent`, `computeIfAbsent`, `String.format`, `java.*`, `System.*`, `ConcurrentHashMap`, `AtomicLong`, `sortedMapOf`, `Regex` features not in common)
1. **HTTP engine factory:** the ktor engine dependency per target (`ktor-client-okhttp` in androidMain, `ktor-client-darwin` in iosMain; add the Darwin artifact to the version catalog), and the client creation (`createHttpClient`, probe client, download client, cover/redirect plugin `OriginSafeRedirects`) moved to commonMain with the engine supplied by a tiny `expect`/factory function or injected `HttpClientEngineFactory`. Timeouts, the logger with redacted headers and redirect rules unchanged. Tests keep using MockEngine.
2. **ABS/Plex API layer to commonMain:** `AbsApiService`, `AbsPaging`, `AbsSessionManager`, `AbsSignIn`, `PlexApiService`, `PlexConnectionProber`, all DTOs under `data/remote/abs/dto` and `plex/dto`, `AbsLibrarySource`, `PlexLibrarySource` (move files, fix imports; replace JVM-only calls; platform identifiers such as the Plex client identifier/product/version come through the existing `PlexClientIdentifier` style interface with an iOS implementation using `NSUUID`/`UIDevice` stored in DataStore, and device info for ABS). Keep package names so imports elsewhere do not change.
3. **Stores and paths:** `AppSettings`, `ServerStatusStore`, credential, stats and other DataStore-backed stores get their DataStore from a common `createDataStore(producePath)` and a platform `PathProvider` (Android: `context.filesDir`/datastore dir as today, so existing files are found; iOS: the app's Application Support directory). Room: an iOS database builder with `BundledSQLiteDriver` and a path from the same provider; Android unchanged. Move `Migration8To9` (androidMain, `SupportSQLiteDatabase`) to a common `Migration` using the connection API (`androidx.sqlite.SQLiteConnection`), keeping its tests/behaviour.
4. **Credentials:** the `CredentialStore` port already exists; add the iOS implementation on the Keychain (`SecItemAdd`/`SecItemCopyMatching`/`SecItemUpdate`/`SecItemDelete`, `kSecClassGenericPassword`, accessible after first unlock, this device only), same keys and JSON shapes as Android. Android keeps AES-GCM/Keystore.
5. **Connectivity and app info:** `ConnectivityMonitor` on iOS with `NWPathMonitor` (online flag, current network id/changes, metered via `isExpensive`); `AppInfo` on iOS from the main bundle (`CFBundleShortVersionString`).
6. **Koin:** split `KoinModules.kt` so common bindings (repositories that can already be common, API services, stores, view models that need no Android) are in `commonMain` modules and platform bindings in `androidMain`/`iosMain` modules; `initKoin(platformModules)` for iOS exposed to Swift (`doInitKoin` naming as in the koin skill); `KoinModulesTest` (verify) must still pass for Android and cover the common module set. Anything that still needs Android-only classes (repositories using java.io, playback, downloads) stays in androidMain for now: do NOT move `BookRepositoryImpl`/sync glue in this step (step 2).
7. **iOS app shell:** `MainViewController` starts Koin once and hosts the real app navigation restricted to what works on iOS now: a minimal iOS root that shows Settings -> Servers (add/edit server, sync status where it needs no unmoved class; where a screen needs a binding that is not shared yet, provide a clearly named iOS stub that returns an empty/"not available on iOS yet" state, tested). Update `iosApp/ChapterPlayer/*.swift` (call `initKoin`), `iosApp/project.yml` (Info.plist keys: `NSLocalNetworkUsageDescription` text, `NSAppTransportSecurity` allowing plain-http servers via `NSAllowsArbitraryLoads` or `NSAllowsLocalNetworking`, background audio mode placeholder is NOT needed yet) and keep the deployment target iOS 16.
8. **CI:** make sure the macOS job still links the framework and builds the app; add a Kotlin/Native compile of `commonTest`/iOS test sources only if cheap. No new Mac-only manual steps.

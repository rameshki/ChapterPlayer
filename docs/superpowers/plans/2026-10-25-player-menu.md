## Verified server behaviour (ABS 2.37.1, real server, throwaway user)
- `PATCH /api/me/progress/{itemId}` with `{ "isFinished": true }` (alone or with currentTime/duration/progress): the item becomes finished, `progress` = 1, `currentTime` keeps its value.
- `PATCH ... { "isFinished": false }`: the server RESETS the item to not started (currentTime 0, progress 0), even if a currentTime is sent. So "Mark as not finished" means "start over" and the client must adopt what the server answers (re-read `GET /api/me/progress/{itemId}` after the PATCH) instead of assuming.
- A progress row can be 404 for a never-started item: marking such a book finished must create it (PATCH works, verified).

## Design (decided; deviate only with a stated reason)
- **Source abstraction:** `BookDownloader.plan()` currently reads `GET /api/items/{id}` audioFiles (ABS). Introduce a small `DownloadSource` port per server type: `plan(book, server) -> List<PlannedFile>` (ordered files with a stable id, file name/extension, total bytes, duration), and `request(server, file) -> how to fetch it` (URL under the CURRENT `server.baseUrl`, auth headers, same-origin redirect rule). ABS keeps its behaviour exactly (bearer, refresh once on 401, `/api/items/{id}/file/{ino}/download`). Plex: tracks from `PlexLibrarySource.fetchContent` (the ordered `PlexTrack`s: part key, length, container, size); file id = the track's rating key; URL = `<baseUrl><part.key>` (the part's download path; no token in it); header `X-Plex-Token` from the server row; extension from the container (fallback `.audio`); a track without a known size is planned with size 0 and fetched without the length check only if the server sends Content-Length (else fail clearly "Plex did not report the file size"); durations from the track length (so `download_files.durationMs` is filled and offline timelines work).
- **Fetching:** reuse `FileDownloader` unchanged in behaviour (Range resume, stall watchdog, no overall timeout, 200/206/416 rules, atomic rename, no redirect to another host: the token header is only sent to the server's own origin; a Plex 401 = `SignInRequiredException` and blanks the token via the existing `markSignedOut` callback; "Sign in again"). The connection can change mid-download (home Wi-Fi <-> remote): each request/retry resolves the server's CURRENT base URL and, on a connection failure, goes through the existing `PlexConnectionManager` re-probe (`onConnectionFailure`) and resumes the same `.part` file with Range.
- **Playback:** `choosePlaybackSource` plays a DONE Plex download from the phone (online: Plex has no session to open, so it simply plays locally and the existing Plex timeline/scrobble reporting continues when online; offline: no session, position queued as for ABS). `playableFromPhone` builds the single timeline from the stored per-file durations and chapters (Plex chapters were stored with the book details; if a downloaded Plex book has no stored chapters or lengths, fall back to one chapter per file and say nothing). The player reads `file://` items as it does for ABS.
- **UI:** the Download control (details, player menu, Downloads tab) appears for Plex books too. For a merged book with both copies downloadable, Download uses the source sheet exactly like Play (rows per copy with size/reachability; the preference setting decides when it can: "prefer downloaded copy" now means: if one copy is already downloaded, offer nothing to download unless the user asks for the other). Remove the "Plex downloads are not available yet" note and the "Download from Audiobookshelf" label for merged books. The Downloads tab lists Plex downloads with a small source label. Storage and Wi-Fi-only rules apply to both.
- **Mark/remove/cancel/pause/resume, DownloadLengthFiller, space check, one book at a time:** all work for both sources through the same `downloads` / `download_files` tables (no schema change expected; if the file id column is currently named `ino`, keep the name and store the Plex rating key there, documenting it).
- **Do not** change ABS download behaviour or file layout (`<root>/downloads/<serverId>/<bookId>/`).

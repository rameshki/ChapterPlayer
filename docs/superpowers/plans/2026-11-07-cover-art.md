# Cover art for the lock screen, the media notification and Android Auto

Branch `stage-4/cover-art`. Read `docs/PROJECT_STATUS.md` and `CLAUDE.md` (Playback, Android Auto, Plex covers, tokens). Today no media metadata carries artwork: covers need the server token (ABS bearer, Plex `X-Plex-Token` header) and the token must never be in a URI, a log, an exception or media metadata. Result: the notification, the lock screen and the car show no cover. Robert wants covers there.

## Design (decided)
- **Notification / lock screen / Bluetooth / watch (the playing book):** embed the artwork BYTES in the player's current `MediaMetadata` (`setArtworkData(bytes, PICTURE_TYPE_FRONT_COVER)`), not a URI. Load them in the service process through the app's authenticated image path (the same Coil loader / `PlexCoverInterceptor` / OriginSafeRedirects rules used by the UI, so tokens go only to the server's own verified origin), downscaled to at most 512 px on the long side (JPEG, quality ~85, memory-safe: decode with sampling), cached in memory (small LRU, a few covers) and on disk by Coil's own cache. Implement as a Media3 `BitmapLoader` for the session (custom class wrapping the authenticated loader) and/or set artwork data when the item is prepared (investigate which is robust with the repo's Media3 1.11 `MediaLibrarySession` and `SkipByTimePlayer`); a failure or an offline server just means no artwork (never an error, never a retry storm). For a downloaded book use the stored `cover.jpg` in the book's download folder first (works offline).
- **Android Auto browse lists (book rows, folders):** a `ContentProvider` `CoverProvider` in the app (authority `<applicationId>.covers`, path `/cover/<bookId>`, NOT exported to arbitrary apps: `exported=true` but each `openFile`/`query` checks `Binder.getCallingUid()` -> package names against the same trusted car packages as `isTrustedCarController` (`TRUSTED_CAR_PACKAGES` + this app); everything else gets `SecurityException`; read-only; no directory listing; no ids other than book ids; `bookId` validated against the library). It streams the (downscaled) bytes from the authenticated loader or the download folder through a pipe/`ParcelFileDescriptor` (or a cache file in `cacheDir` with a hashed name). `CarItem.coverUrl` stays as is (domain), the mapping in androidMain (`CarMediaMapping`) sets `artworkUri` to the content URI, never the server address. The provider also serves the notification if easier, but the bytes-in-metadata path is preferred there.
- **Never:** tokens in the content URI, in logs, in exceptions; cover requests to hosts other than the book's own server (reuse `plexTokenFor`-style origin rules); covers of books of removed servers; loading while on mobile data? (no extra rule; covers are small).
- iOS: out of scope here (the iOS player sets now-playing artwork separately; note in docs if relevant).

# Jellyfin J3: recorded shapes, downloads, Quick Connect

Plan for review finding R39 (17 Nov 2026). It replaces the outline at the end of `2026-11-08-jellyfin-j1-j2.md` ("Stage J3").
Spec: `docs/superpowers/specs/2026-11-07-jellyfin-source-design.md`. Rules: no real server address, id, title, token or password in
the repo, in fixtures, in logs or in prompts; fixtures keep the real structure with invented values.

**Goal:** a Jellyfin book downloads and plays offline; Quick Connect signs in; the Jellyfin fixtures come from recorded answers.

**Why this order:** the fixtures were written from the API description and the real answers were never recorded. Recording first
means the download and Quick Connect code are built on the real shapes, and any parsing fault in J1 and J2 is found before more is
built on it.

## What already exists (checked on main, 19 Nov)

- `ServerSource.canDownload()` is false for Jellyfin (`domain/browse/SourceChoice.kt`); Jellyfin has no Download control.
- The downloader core is common code and source-agnostic: `DownloadSource` (`plan`, `authorized`, `authorizedSmall`,
  `afterConnectionFailure`), `BookDownloader`, `FileDownloader` (one ranged GET per file into `<ino>.<ext>.part`, renamed when
  complete), `DefaultDownloadController`, `DownloadLengthFiller`. `AbsDownloadSource` and `PlexDownloadSource` are the two
  implementations; Koin binds both.
- Jellyfin streaming already authorises with the `Authorization: MediaBrowser ...` header (`jellyfinStreamHeader`,
  `AuthorizingDataSourceFactory`), never in the URL. `JellyfinApiService` has the browse, progress and played calls.

## Task 1: record the real answer shapes (needs the owner's server)

- A script `tools/jellyfin-record/record.py` (Python standard library only), run by the owner or by Claude over a private channel,
  with a throwaway Jellyfin user (created by the owner or through the admin API, with the Download permission, deleted
  afterwards). Credentials come from environment variables, never from arguments or files in the repo.
- Calls to record, each as a fixture with every value replaced by an invented one of the same shape (ids stay 32 hex digits,
  titles become "Test Book N", tick counts keep their magnitude): `GET /System/Info/Public`, `POST /Users/AuthenticateByName`,
  `GET /Users/{id}/Views`, `GET /Items` (audiobook list with the fields J1 asks for), `GET /Items/{id}` (single file and a
  multi-file folder if the library has one), `GET /Items/{id}/Images/Primary` (headers only), `POST /Sessions/Playing`,
  `/Playing/Progress`, `/Playing/Stopped`, `POST /UserPlayedItems/{id}`, `DELETE /UserPlayedItems/{id}`,
  `POST /UserItems/{id}/UserData`, `GET /QuickConnect/Enabled`, `POST /QuickConnect/Initiate` (and `Connect` while waiting).
- For `GET /Items/{id}/Download` record only the status and the headers: `Content-Length`, `Content-Type`,
  `Content-Disposition` (file name and extension), `Accept-Ranges`, the answer to `Range: bytes=0-0` (206 and `Content-Range`),
  and the answers with a user that lacks the Download permission (403) and with a bad token (401). Never save the body.
- Compare each recorded shape with the existing fixture and parser; fix what differs (nullable fields, missing `RunTimeTicks`,
  chapters, tick units) with a test per fix. This finds what the two days of real use have not.
- **Done when:** every recorded call has a fixture under `shared/src/androidHostTest/resources/fixtures/jellyfin/` and a parsing test, and
  the open rows of the J2 phone check can be run (see Task 5).

## Task 2: `JellyfinDownloadSource`

- `data/downloads/JellyfinDownloadSource.kt` implementing `DownloadSource` with `type = JELLYFIN`:
  - `plan`: one `PlannedFile` per book (the spec decided one `.m4b` per book): `ino` = the item id, size from
    `MediaSources[0].Size`, extension from `MediaSources[0].Container` (else the `Content-Disposition` name), chapters from the
    item's `Chapters` (start ticks to milliseconds), length from `RunTimeTicks`. A book with no size or no length is refused at
    plan time with the streaming text, as Plex does, because it could never play offline.
  - `authorized`: `GET {baseUrl}/Items/{id}/Download` with the `MediaBrowser` header per request (built from the stored token, as
    streaming does), a ranged GET for resume. 401 gives `SignInRequiredException` (Sign in again, the token is not refreshed);
    403 fails the book with a plain message ("This account may not download from the server"); 404 raises
    `DownloadFileGoneException`.
  - `authorizedSmall` for the cover with no `Authorization` header (covers are anonymous in Jellyfin) and the origin check the
    other sources use.
  - `afterConnectionFailure`: null (one address, no relay logic).
  - The token never appears in a URL, a log line, an exception message or the notification.
- Koin: bind it next to the other two sources (`KoinModulesTest` shows what it still needs).
- Tests with the recorded fixtures and a mock engine: the plan for a single file, a refused plan (no size), 401, 403, 404, a
  resumed `.part` (Range), a cover with no header, no token in any request URL, a redirect to another host dropped.

## Task 3: switch it on

- `ServerSource.canDownload()` true for Jellyfin; Jellyfin joins the Download control on Book details, the long-press menu, bulk
  Download, "Download from" in Settings (a line per Jellyfin server when there are two or more) and the merged-copy sheets.
  `playableFromPhone` matches a Jellyfin download by `PlaybackTrack.fileId`.
- A downloaded Jellyfin book plays from the file with the existing offline path (`choosePlaybackSource`) and its progress goes
  through the queue when the network returns, as for the other two sources.
- Update `docs/architecture/downloads.md`, `jellyfin.md` and the Downloads settings text (it says Jellyfin has no downloads).

## Task 4: Quick Connect (spec 5.1)

- `domain/jellyfin/QuickConnect.kt`: the next step from the elapsed time and the last answer (wait, sign in, expired after 5
  minutes, not approved, off) with its texts. API: `GET /QuickConnect/Enabled`, `POST /QuickConnect/Initiate`,
  `GET /QuickConnect/Connect?secret=` every 5 s, `POST /Users/AuthenticateWithQuickConnect`.
- The setup handler gains a Quick Connect step (the code, "Waiting for approval", Cancel; one wait at a time; cancelled with the
  view model) in Add Server and in Sign in again. The secret lives in memory only, is masked in the debug HTTP logger
  (`secret=`), and is never in `toString` or a log.
- Tests: expiry, 401 or 404 on Connect, Initiate 401 means off, cancel stops the polling, the same `DeviceId` on Initiate and
  sign-in, the secret never in logs or `toString`.

## Task 5: finish the J2 phone rows, then the J3 rows

- J2 rows still open (`DEVICE_CHECKS.md`): two minutes in the resume band keeps the real place; stopping in the last five minutes
  is not finished unless it ended; offline listening delivered later.
- J3 rows: a Jellyfin book downloads (progress, pause, resume, removal), plays in flight mode, its place reaches Jellyfin when the
  network is back; an account without the Download permission gets the plain message; Quick Connect signs in from the Jellyfin
  web page's approval.
- Record each result in `DEVICE_CHECKS.md` with the build number.

## Order, effort, risk

1 then 2 then 3 are one chain (about three to four days with the recording). 4 is independent and can go in parallel (about one to
two days). 5 follows each. Biggest risk: Jellyfin's `/Items/{id}/Download` may not honour `Range` on every version; Task 1 records
it, and if it does not, resume restarts the file (`FileDownloader` already truncates when the server answers 200).

## What the owner needs to do

Create a throwaway Jellyfin user with the Download permission (or give an admin API key for one session) and say when the script
may run against the server; the user and the key are deleted afterwards.

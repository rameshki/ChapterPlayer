## Research notes (2026-10-18; check the sources again before relying on a number)
- **Context window.** Ollama's own default context is small (2048 or 4096 depending on VRAM) and a longer prompt is silently truncated; agents with tool schemas can run out before doing work. OpenClaw sets 32,768 for local models (confirmed on this laptop: `ollama ps` shows CONTEXT 32768), and its docs say it works best at 32K or more. Keep prompts well under that. If answers look like they ignore the end of a long prompt, check `ollama ps`.
- **Output cap.** OpenClaw defaulted local models to 8,192 output tokens (now 16,384 here) and stops "repetitive" output with `[Repetitive output stopped]`. Raise with `params: { num_predict: ... }` or `maxTokens` in the provider config (not changed on this machine).
- **Native API only.** OpenClaw's docs say never to point it at Ollama's `/v1` URL (it breaks tool calling); native `baseUrl` has no `/v1`. Thinking defaults to off for Ollama (`params.thinking`).
- **Sampling.** Qwen's recommended settings for Qwen3-Coder (30B-A3B): temperature 0.7, top_p 0.8, top_k 20, repeat_penalty 1.05; they are already the model defaults here (`ollama show qwen3-coder:latest`). A user report prefers temperature 0.1 to 0.2 for code edits (anecdote). OpenClaw forwards `temperature`, `top_p`, `top_k`, `repeat_penalty`, `num_predict`, `keep_alive`, `think` from `params` under `models.providers.ollama.models[]`.
- **Speed.** `ollama ps` shows the 18.6 GB model split 33% CPU / 67% GPU, which is why agent runs take minutes. A smaller context frees GPU memory; a smaller model (for example `qwen2.5-coder:14b`) may fit fully.
- **Prompting small models (general).** State the output format explicitly, constrain length and scope, split large tasks, show one to three input/output examples including an edge case (research on few-shot code prompts: arXiv 2412.02906; prompt-defect taxonomy: arXiv 2509.14404). No source studied tests-first prompting; our own result is the evidence for it.

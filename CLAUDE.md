# ChapterPlayer

Audiobook player for Audiobookshelf, Plex and (later) Audible. Android first,
built with Kotlin Multiplatform so it can port to iOS. See `docs/ROADMAP.md`
for scope, stages and design direction. Keep that file updated as stages complete.

**Start here in every session:** read `docs/PROJECT_STATUS.md` first. It is the ongoing project status and progress document (what is merged and open, what is verified on devices, next steps, process, device-testing notes, traps) and must be updated whenever a block of work finishes.

## Priorities
- Sources: Audiobookshelf > Plex > Audible (Audible scope undecided; never remove DRM)
- Must have: Android Auto, widgets, offline downloads; later CarPlay + iOS widgets
- Design reference: AudioBooth (iOS ABS client): tabs, home shelves, player sheet, mini player. Borrow structure, not code (MPL-2.0).

Play in the Resume state is the Continue widget's `resume_book_id` path (`WidgetResumer`); the controls are `Listen*Action` callbacks through `WidgetActions` (`previousChapter` / `nextChapter` use `remoteAction`), which act on the loaded book only (`runWidgetButton`, shared with Now Playing); the body opens the player while a book is loaded. `WidgetRefresher.listen` is `WidgetStates.listen` computed once and shared (the refresher and the widget's session), only while a Listen widget is placed (`WidgetHost.listenPlaced` at start, then the receiver's onEnabled / onDisabled and every `provideGlance`); it redraws Listen at once for the controls and debounced like Continue for the Resume state, and asks `WidgetCovers.prefetch` for the shown book's cover off the redraw when the state changes, the network comes back or the widget is drawn (`requestCover`, from `provideGlance`: placed, resized, a system update); `coverNextStep` redraws once on a new cover and retries a failure after the loader's 60 s backoff while online, at most 3 tries. The refresher also asks for the covers of the books Now Playing and Continue Listening show (a `NowPlayingWidgetState.Book` carries its `bookId`) and redraws all three when one arrives (Listen only while placed); every widget's `provideGlance` calls `requestCover`. Android's `WidgetCoverCache` (`ui/widgets`, was `ListenCoverCache`) loads covers in the app through `CoverBytesLoader` (downloaded cover first, token only in a header) only while some widget of the app is placed, decodes them as RGB_565 to at most 256 px (`WIDGET_COVER_MAX_SIDE`, `AndroidCoverScaler.decodeScaledBitmap`; 128 KiB per cover; Listen's four cover buckets hold the same bitmap, so at most 512 KiB per placed widget if each were sent apart, 128 KiB when the size map shares its bitmap cache as on Android 12+) and keeps the last 3 per book id (at most 384 KiB); the widgets get a bitmap, never an address. R8 renames `ListenWidget` (like the two older widget classes; no keepnames rule, nothing shows it causes harm: the system sends APPWIDGET_UPDATE after a package update). Host-tested only
- Stats: `ListeningRecorder` (`data/stats`, app-scoped, started by the application) watches `PlaybackController.state` and logs listening per local day and book into `listening_log` (Room v11; wall and book seconds, server, source). Time counts only while sound plays: no seeks, no buffering, no gaps over 5 s. The log is written every ~30 s and on pause or stop; after a failed write it waits 5 s, doubling to 5 min. `ListeningStatsImporter` (bound as `ListeningImport`) imports Audiobookshelf's `GET /api/me/listening-stats` once per server into `imported_listening_days` / `imported_listening_items`; `listening_imports` records which servers were imported. Each item row stores `loggedAtImport`, the app's logged total for that book at the import. A failed first import retries after 30 s, doubling to 30 min, and at once when the server row changes or the network returns. It is never tried while offline or while the server needs a sign-in. The stats page's Refresh imports again. ABS `days` keys are server-zone dates, read as phone-zone days. Rules: a day counts the larger of the log and the summed imported history; the source split adds the history beyond the log as ABS, so it sums to the total. All-time top lists add each book's server total minus `loggedAtImport` on top of the log, so they grow with new listening without a Refresh. Days are epoch days in an injected `DayZone` (`SystemDayZone` on Android; no java.time in commonMain). The pure rules (periods, day totals, streaks, top lists, series finished / to finish, heat grid, texts) are in `domain/stats` with host tests. `ui/stats` holds `StatsScreen`, `StatsViewModel` (route `stats`, from the Library top bar and Settings; a minute ticker follows midnight) and `HeatColors.kt`, where `HeatColorsTest` checks the level contrast in both themes. Host-tested only

- Server tokens live in an AES-GCM encrypted DataStore (`CredentialStore`) keyed by the Android Keystore (iOS: `KeychainCredentialStore`, generic-password items of service `com.chapterplayer.credentials`, the same keys, after first unlock, this device only), not in Room (the Room `token` column stays, empty). Audiobookshelf signs in with username and password (`AbsSignIn`, port `AbsSignInPort`) and keeps a refresh token (`<serverId>.refresh`); `AbsSessionManager` refreshes the access token before it expires and on a 401 (one refresh at a time per server; a rejected refresh means `SignInRequiredException`, shown as "Sign in again" in Settings). - Dependency injection is Koin (Classic DSL). `commonMain/.../di/CommonModules.kt` holds the shared bindings and the qualifiers (`commonModules`: DAOs, network, stores, sources, servers and sync, `commonRepositoryModule` (the book repository), `commonBrowseModule`, `commonPlaybackModule` (progress, queue, mirrors, bookmarks, history, stats, `PlaybackStarter`) and every view model; each platform provides the database, the DataStores, the credential store, the Plex client id, connectivity, `AppInfo`, the debug flag, `BlockingIoQualifier`, `DayZone`, `ListeningClock`, and the player and download parts: `PlaybackController`, `LocalBookFiles`, `DownloadController`, `DownloadStorage`, `DownloadOverview`, `NotificationPermission` and `PlatformFeatures`); Android's modules in `androidMain/.../di/KoinModules.kt` include them (`sharedModules`, started by the Application); iOS starts `commonModules` + `iosModules` (platform, `iosPlaybackModule`, `iosDownloadModule`) through `initKoin` (`di/KoinStart.kt`, once); its platform module is `platformModule(PlatformParts)` (`di/PlatformModule.kt`), which `KoinModulesTest` builds from fakes so a missing qualified binding fails.

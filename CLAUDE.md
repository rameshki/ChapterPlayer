# ChapterPlayer

Audiobook player for Audiobookshelf, Plex and (later) Audible. Android first,
built with Kotlin Multiplatform so it can port to iOS. See `docs/ROADMAP.md`
for scope, stages and design direction. Keep that file updated as stages complete.

## Priorities
- Sources: Audiobookshelf > Plex > Audible (Audible scope undecided; never remove DRM)
- Must have: Android Auto, widgets, offline downloads; later CarPlay + iOS widgets
- Design reference: AudioBooth (iOS ABS client): tabs, home shelves, player sheet, mini player. Borrow structure, not code (MPL-2.0).

## Current state
- Three parts: `shared/` (Kotlin Multiplatform, Android + iOS targets; all app code), `androidApp/` (activity, manifest) and `iosApp/` (SwiftUI host; its Xcode project is generated from `iosApp/project.yml` with XcodeGen). `iosMain` is only a placeholder screen until Stage 5. The macOS CI job links the framework and builds the app, and cannot be run on Windows
- Stack: Compose, Koin, Room (KSP), Ktor + kotlinx.serialization on Kotlin 2.4, AGP 9.3 (built-in Kotlin), Gradle 9.5, compileSdk 37
- UI is Compose Multiplatform (plugin 1.12.1). The theme, fonts (`shared/src/commonMain/composeResources/font`), components, screens, view models and navigation are all in `commonMain` (JetBrains navigation and lifecycle). `androidMain` keeps only what is Android-specific: the HTTP client setup, the repository and API implementations, the Android client identifier and the Koin modules. Images load with Coil 3
- The theme follows `AppSettings.themeMode` (Dark, Light, Follow system; new installs follow the system). `ui/theme/Palette.kt` holds the dark and light palettes; the colour names in `Color.kt` (`AmberGold`, `TextSecondary` etc.) are composable properties that read the current palette, so read them inside composables only (a draw lambda must read the colour first). `PaletteContrastTest` guards text contrast in both themes. The launch window colour is in `values/themes.xml` (light) and `values-night/themes.xml` (dark)
- Browsing: pure rules live in `domain/browse` (filters, sort, search, grouping by author/narrator/series/collection, offline rules; tested without Android). `libraries`, `collections` and `collection_books` tables hold the server's library list and collections (Room v3, auto-migration). `LibrarySyncCoordinator` (`data/sync`, an app-scoped Koin single) is the only thing that syncs: it keeps one sync per server at a time, queues one follow-up when libraries change, and survives cancellation. Library views, layouts and filters are in `ui/library`; the Libraries check-list is `LibrariesSheet`
- Playback: one Media3 `MediaLibraryService` (`PlaybackService`, in `shared/androidMain/.../data/playback`) hosts one ExoPlayer; the UI talks to it through `PlaybackController` (`AndroidPlaybackController` wraps a `MediaController`). Audiobookshelf is asked for a playback session (`POST /api/items/{id}/play`); a book with several audio files plays as ONE timeline (one media item per file; `domain/playback` maps book position to file and offset). Audio is fetched with the bearer token added per request by `AuthorizingDataSourceFactory` (refreshed once on a 401). The pure rules (timeline, sleep timer, rewind on resume, skips, speeds) are in `domain/playback` with host tests; the service behaviour itself is checked on an emulator (`adb shell dumpsys media_session` shows state and position)
- Player UI: `ui/player` holds the full player (`PlayerScreen`, speed/sleep/chapter sheets), the mini player (above the tab bar, hidden on the player and Settings routes) and `PlayerViewModel`, all reading `PlaybackController.state`. `PlaybackStarter` (`data/playback`) is the one way to start a book (Home, details); `PlaybackProgressSaver` saves progress app-wide. Pure display rules live in `domain/playback/NowPlaying.kt`, `domain/browse/ResumeCard.kt` and `ContinueSeries.kt`. The notification opens the player through the `open_player` intent extra. The player's top-right More options (three dots) menu is `PlayerMenuButton` with its own `PlayerMenuViewModel` (menu state and actions; results show as a snackbar): Book details, More by <author> (only when the author has other books), Open series (only with a series), the download item (Download / Pause / Resume / Try again / Remove download with a confirmation; hidden for Plex), Mark as finished / not finished (Audiobookshelf and Plex; for Plex it scrobbles / unscrobbles every track) and Settings. `BookRepository.markFinished` changes the local progress first (rules in `domain/playback/MarkFinished.kt`), then PATCHes `/api/me/progress/{id}` and adopts the server's answer (an un-finished book is reset to 0 by the server); when the server cannot be reached the mark waits in `pending_progress` (Room v8, column `markedFinished`) and the flusher delivers it. `PlaybackProgressSaver` saves through `savePlaybackProgress`, which reads and writes under the same lock as `markFinished` and keeps a finished mark the user made while that book is loaded (re-derived on every save, never latched; a finished row merged from the server does not count)
- Progress: `PlaybackProgressSaver` saves locally every 10 s while playing; `ProgressSyncer` sends the position through the ABS playback session every ~10 s and, when that fails, writes one coalesced row per book into `pending_progress` (Room v4); `PendingProgressFlusher` delivers the queue (on start, when the network returns, with backoff) and drops a queued row when the server holds something newer; a live sync the server took also deletes the older queued position of that book (never a queued mark), so it cannot be replayed over newer listening. The pure decisions (newest wins, timing, backoff, merge) are in `domain/playback/ProgressSync.kt`. Audiobookshelf progress is merged into local progress during the library sync; for both ABS and Plex the server progress is consulted by `PlaybackStarter` when a book opens (Plex is read only then, and when the queue flushes)
- Bookmarks and History: `bookmarks` (Room v5; state SYNCED / PENDING_CREATE / PENDING_RENAME / PENDING_DELETE, identity = book + whole second) merge with the server's `GET /api/me` bookmarks through `mergeBookmarks` (`domain/playback/Bookmarks.kt`); `BookmarkSyncer` (`data/bookmarks`) pulls then pushes at start, when the network returns, after library syncs and a few seconds after a local change. `HistoryRecorder` records the position left on a big jump (`domain/playback/History.kt`, local only, last 10 per book). Player bottom row: Speed, Sleep timer, Bookmarks, History
- Android Auto: `PlaybackService` serves a browse tree through `CarLibraryCallback` (`data/playback`): the tree, ids, letter ranges, voice matching and the trust rule are pure code in `domain/car` (`CarRules.kt`, `CarBrowse.kt`). Only this app and the allowlisted car packages (`TRUSTED_CAR_PACKAGES`) browse or start books; other controllers keep play/pause/seek only. A book requested from the car starts through `PlaybackStarter` (the one load path); Plex books are playable in the car under the same rules as Audiobookshelf streaming books. `AppSettings.resumeOnCarConnect` (Settings, Android Auto) resumes the last book when the head unit connects. No cover art in the car yet (covers need the token)
- Plex connection choice (Stage 4 step 3): pure rules in `domain/plex/PlexConnections.kt` rank plex.tv's connections (local, the raw local `http://<address>:<port>` for a `*.plex.direct` local name, remote, relay; IPv6 only when nothing else), probe them (`pickConnection`: two at a time, a lower-ranked answer waits a 1.5 s grace window for better-ranked ones, a timeout is tried once more, and a local plex.direct name that is not found moves the raw local address ahead of remote; `probeAll` for Test connection), classify errors by type name (`classifyConnectionError`, no JVM types in common code) and word the result (`connectionNote`). `PlexConnectionManager` (`data/sync`) writes the winner into the server row's `baseUrl` (so every caller uses it) and keeps the ranked list, the last probe and its note in `ServerStatusStore` (a Preferences DataStore `server_status`, one JSON record per server; no Room change). It re-probes after a connection failure (sync: retry once on the new address; playback start: `BookRepositoryImpl.onConnectionFailure`), when `ConnectivityMonitor.currentNetwork` changes (started by the Application) and before the first sync of a server with no choice yet; at most once per 30 s unless forced (Sync now, Test connection). A server saved before this asks plex.tv for its list (`PlexTvCandidateLookup`, matched by address). The probe (`GET /identity`, client `createProbeHttpClient`: 5 s timeouts, no redirects) sends NO token, and only an answer naming the server's `machineIdentifier` (plex.tv's `clientIdentifier`, kept as `machineId`) counts; a bare 2xx (captive portal, another Plex server) loses. Besides the address in use, the token goes only to `verifiedUris` (`ServerConfig.alternateBaseUrls`, filled by `ServerRepositoryImpl`; `plexAddressesOf`): https connections that answered as the server, and a plain http (raw LAN) one only while verified on the current network. On a network change plain http verifications are dropped and a server on a raw LAN address is moved back to its first https connection before it is probed again; a sync of an unverified plain address probes first. After a remote or relay pick the local connections are tried again 60 s later. A switch the caller did not ask for (`onSwitched`) syncs that server again (`requestSync`), so stored cover addresses follow the address in use. A Plex edit that changes the address or token by hand forgets the connections (`forget`). Probes and plex.tv reads run on the injected IO dispatcher. Built against fixtures and fakes; NOT tried on a real Plex server
- Sync status: `LibrarySyncCoordinator.serverStatus` gives each server's phase (`Idle` with last success and cached book count, `Syncing`, `Failed` with a short reason from `syncFailureReason`), the connection in use and the last Plex probe; the last success and error persist in `ServerStatusStore`. `syncNow(serverId)` and `syncNowAll()` (the Library refresh button and pull to refresh) force a sync, still one per server at a time. Settings, Servers (`ServersViewModel`, wording in `domain/settings/ServerStatusText.kt`) shows each row with Sync now and, for Plex, Test connection (a dialog of every connection with OK or the reason; never a token)
- Plex (Stage 4): in a Plex music section each audiobook is an ALBUM (the top level lists artists). `PlexLibrarySource` (`data/source`) lists `/library/sections/{key}/all?type=9` in pages of 200 (`fetchAllPlexItems`, `data/remote/plex/PlexPaging.kt`; follows `totalSize` even when a server sends smaller pages); a server that answers with artists has each artist opened for its albums. Book id `plex_<album ratingKey>`, author = album `parentTitle`, no narrator. A sync reads the section list once; a section that fails keeps its cached books (`SourceSnapshot.failedLibraries`) and is reported, only all sections failing fails the sync. Opening a book (`fetchBookDetails`) reads the album, its tracks (`/children`) and the first track with `includeChapters=1` (every track, 4 at a time, when that one has chapters or failed; a track whose detail fails is one chapter); `plexBookContent` (`domain/plex/PlexBookContent.kt`) builds the chapters across tracks and the ordered `PlexTrack`s (part key, length, container, size) that playback will use, and details store the book's length (a section listing has none). The token is never in a stored address: API calls send `X-Plex-Token`, and covers get it from `PlexCoverInterceptor` (`data/images`, installed as Coil's image loader by the Application, whose Ktor client follows redirects itself and drops `Authorization` and `X-Plex-Token` when one leaves the origin: `data/remote/OriginSafeRedirects.kt`) only for addresses under a signed-in Plex server (`plexTokenFor`, `domain/plex/PlexImageAuth.kt`). Room v9 changes no table: its migration (`Migration8To9`) dropped the Plex rows stored as artists with the token in their addresses, plus progress, queued progress, history and bookmarks for `plex_` ids. Playback (step 2): Plex books stream like Audiobookshelf books that are not downloaded (online only; no Plex downloads, the Download control stays hidden). `PlexLibrarySource.startPlayback` reads the tracks and chapters fresh (`fetchContent`) and builds the app's own session (Plex has none): one media item per track on the one timeline, each address the part path under the server address with no token (`plexPlaybackTracks`, `domain/plex/PlexPlayback.kt`). `AuthorizingDataSourceFactory` adds `X-Plex-Token` per request only for addresses under a Plex server (`openAuthorized`), and a 401 is `SignInRequiredException` ("Sign in again", no refresh: Plex tokens are long lived). Audio is fetched through `OkHttpDataSource` with redirects off; `openStream` follows them by hand (`redirectTarget`: at most 5, never https to http, and a request carrying a token, ABS bearer or Plex header, only to the same scheme, host and port, else `UnsafeRedirectException`). A track without a file or without a known length fails the start with a safe message. A 401 on a Plex playback or progress call (start, timeline, scrobble, track list) blanks the server token (`markSignedOut`, wired in Koin) and is `SignInRequiredException`, so the flusher stops and Settings shows "Sign in again". The notification has no artwork for ABS or Plex (an artwork address would need the token). Resume: `fetchProgress` reads the track list (`viewOffset`, `viewCount`, `lastViewedAt` per track) and `plexServerProgress` gives the finished tracks plus the offset in the track in progress, finished when every track was played, updated at the newest `lastViewedAt`; the starter weighs it against local progress (newest wins). Progress push: `ProgressSyncer` reports Plex books too; `syncPlayback` sends `GET /:/timeline` (ratingKey, key, state `playing`, `paused` for the report on pause, `stopped` only from `closePlayback`, time and duration in the track, `identifier=com.plexapp.plugins.library`, client headers from `PlexApiService`, whose client identifier is required) for the track that holds the position, and `GET /:/scrobble` once per session for a track that playing went through (its end lies between two reports no further apart than the time listened at 3x plus 5 s; a seek over tracks scrobbles nothing) or whose last 5 s are reached (`plexCompletedTracks`). A session that never reported (a rolled-back start) closes silently. Once the book is set finished (`pushProgress` with finished, e.g. Mark as finished while it plays) its live session sends nothing more, so a later timeline cannot undo the mark; set not finished, it reports again. `plexServerProgress` counts every track played with at most one offset left as finished. An unknown session (after a restart) fails, so the position is queued in `pending_progress` as for ABS; `pushProgress` (queue, Mark as finished / not finished) follows `plexProgressPlan`: unscrobble the played tracks from the position's track on, a stopped timeline for the offset, scrobble the unheard tracks before it (finished = scrobble every track). The library sync merges no Plex progress (that would need one call per book). Built against recorded-shape fixtures in `fixtures/plex` and mock servers; NOT yet tried on a real Plex server or a phone
- Downloads (Stage 3): `DownloadController` (commonMain; `DefaultDownloadController` over a `DownloadScheduler`, WorkManager on the phone) queues, pauses, resumes and removes books; status and bytes live in `downloads` / `download_files` (Room v6; v7 adds each file's length and type) and only change from the expected status (`updateStatusIf`), so a pause or removal is never overwritten. `DownloadWorker` (a dataSync foreground job, unique name `download-<bookId>`, network constraint from `AppSettings.downloadWifiOnly`) runs `BookDownloader` (`data/downloads`): it plans the files from `GET /api/items/{id}` audioFiles, checks the space, and fetches file after file with `FileDownloader` (one ranged GET per file into `<ino>.<ext>.part`, renamed when complete; its own Ktor client with no request timeout, a stall check before and after the headers, refresh once on 401, no redirect to another host, disk errors fail instead of retrying). One job per book and one book at a time; `DownloadJobs.whileIdle` is how deletes wait for a stopping job. New downloads go to `<root>/downloads/<serverId>/<bookId>/`, the root being the Settings choice (`SettingsDownloadLocation`: internal storage or the app folder on a mounted external volume / SD card, falling back to internal); a planned download stays in the folder its `download_files` paths name, and removal deletes the folders those paths point to, so changing the location affects new downloads only. The pure rules are in `domain/downloads`
- Downloads UI: `DownloadOverview` (`data/downloads`, `RoomDownloadOverview`) is what screens read: one `DownloadRow` per book, fraction and bytes from the file rows, speed and time left live from `BookDownloader` (`LiveDownloadProgress`), plus storage used. Book details (`DetailsDownload.kt`, `DownloadControl.kt`) shows Download (with the size from the server), progress, Pause / Resume / Cancel, Try again, and Remove download with a confirmation, for Audiobookshelf books only; the start is disabled offline. The first download asks for notifications once through `NotificationPermission` (`AndroidNotificationPermission`, lent the launcher by `MainActivity`); the download runs either way. The Downloads tab (`ui/downloads`) lists every download (active first, then title) with row buttons and a used / free header. Settings, Downloads: Wi-Fi only (a change reschedules waiting and running jobs, `DownloadController.reapplyWifiSetting`), location, and storage limit (`AppSettings.downloadStorageLimitBytes`, read by the downloader's space check)
- Offline playback: `PlaybackStarter` asks `choosePlaybackSource` (`domain/playback/PlaybackSource.kt`) whether a book streams, plays from the phone or cannot play (offline and not downloaded: "Needs a connection to play"; "Downloaded only" blocks streaming except from the car). `LocalBookFiles` (`RoomLocalBookFiles`) hands out a DONE download's files only when each is on disk at its full size (disk checks on the I/O dispatcher). A book folder that cannot be seen (an unmounted SD card) only means "not playable now"; a folder that is there with a file gone or of the wrong size marks the download FAILED and resets the missing files so Try again fetches them. Removing a download first tells the player (`DownloadRemovalListener` → `PlaybackController.releaseLocalFiles`), which stops a book playing from those files. The controller gets `AudioOrigin.Phone`: online it still opens an ABS session (live sync; if that fails the book plays without one), offline it plays with no session and `ProgressSyncer` queues the position. `playableFromPhone` (`data/playback/PlayableBook.kt`) matches session tracks to files by the ino in their `/file/{ino}` address: the session's timeline when it lists exactly these files in this order, else per-file lengths (the session's for that file, else `download_files.durationMs`, Room v7; a single file uses the book's length). Lengths learnt from a session are saved, and `DownloadLengthFiller` fills missing ones from `GET /api/items/{id}` each time the phone comes online, so downloads made before v7 play offline too. The player reads `file://` items through `DefaultDataSource` and HTTP through `AuthorizingDataSourceFactory`. The car's Downloaded tab lists the downloaded books
- Widgets (Glance 1.2.0, `shared/androidMain/.../ui/widgets`; receivers in the app manifest, provider XML and previews in `shared/src/androidMain/res`): Now Playing (narrow = play/pause, from 180 dp title + back 15 / play-pause / forward 30; the body opens the player through `open_player`) and Continue Listening (Resume opens the app with `resume_book_id`; `WidgetResumer`, in the app scope and one start at a time, starts only the book the widget offers or Home's Resume book through `PlaybackStarter`, then opens the player; a restored or Recents intent is ignored, `shouldHandleWidgetResume`). What they show is pure code in `domain/widgets` (`WidgetState.kt`, `WidgetCommands.kt`); `data/widgets` holds `WidgetStates` (the flows), `WidgetActions` (buttons act on the loaded book only, never load one; with nothing loaded the button opens the app) and `WidgetRefresher` (started by the application; redraws on state changes, not position ticks, Continue debounced) behind `WidgetHost` (`GlanceWidgetHost`). Colours follow `AppSettings.themeMode`; no cover images (a placeholder). R8 keeps the `ActionCallback` constructors (`proguard-rules.pro`)
- Server tokens live in an AES-GCM encrypted DataStore (`CredentialStore`) keyed by the Android Keystore, not in Room (the Room `token` column stays, empty). Audiobookshelf signs in with username and password (`AbsSignIn`, port `AbsSignInPort`) and keeps a refresh token (`<serverId>.refresh`); `AbsSessionManager` refreshes the access token before it expires and on a 401 (one refresh at a time per server; a rejected refresh means `SignInRequiredException`, shown as "Sign in again" in Settings). Libraries the user turned off are stored in `excluded_libraries`. App preferences (theme, library layout, car resume) live in `AppSettings`. Tests that write to a DataStore use `InMemoryPreferencesDataStore`, because DataStore cannot rewrite its file on Windows
- Settings: the gear opens a hub (`SettingsHubScreen`, route `settings`) of rows with live one-line summaries; each row opens its own page (routes `settings/servers`, `/appearance`, `/downloads`, `/car`, `/about`, one small screen file each in `ui/settings`, shared cards in `SettingsComponents.kt`). Every page uses the same `SettingsViewModel` class, but each page gets its own instance (scoped to its back-stack entry; the state is saved settings, so they agree); the summary text rules are pure code in `domain/settings/SettingsSummary.kt`. The empty-state "Add a server" buttons (Home, Library) go straight to the Servers page. The About page reads the version through `AppInfo` (`data/AppInfo.kt`), which `androidApp` provides in `AppModule` (iOS must provide it too before Stage 5). The hub is host-tested for text and routes only, not checked on a device
- Dependency injection is Koin (Classic DSL, modules in `shared/.../di/KoinModules.kt`). Koin fails when a screen opens, not at build time, so `KoinModulesTest` runs `verify()` over every module: add a new class to a module and the test shows what it still needs
- Host tests in `shared/src/androidHostTest` (`./gradlew :shared:testAndroidHostTest`). Parsers are tested against recorded server responses in `src/androidHostTest/resources/fixtures`: real structure, synthetic text, ids, paths and tokens. The repo is public, so never commit real server data

## Building
- Java: JDK 17 (CI uses Temurin 17); full builds are tested on it. Gradle 9.5 also configures the project on Android Studio's bundled JBR 25 (`help` checked; a full compile on JBR 25 has not been run).
- `./gradlew :androidApp:assembleDebug` (needs JAVA_HOME set to JDK 17 or newer)
- SDK: platform `android-37.0` and build-tools `36.0.0` (AGP 9.3 minimum). With `sdkmanager` on Windows use slash paths: `sdkmanager "platforms/android-37.0"`

## Conventions
- Branches `stage-N/<feature>`, PRs into protected `main`, tags `v0.N.0` per stage
- Server tokens never logged (auth headers are redacted in the HTTP logger)
